Abstract
Manipulation benchmarks randomize what the world looks like — backgrounds, lighting, clutter — but keep what the world is like fixed: friction, mass, restitution, gravity-aligned tables, and calibrated cameras are hard-coded constants. RoboTwin-Phys turns the world's physical parameters into controllable, labelable variables. Across 13 physical factors on 50 bimanual tasks, we build tiered perturbation configurations with measured failure envelopes, fixed-seed paired evaluation, and per-episode ground truth: exact physics values, contact-force logs at 250 Hz, object kinematics at 50 Hz, and failure timelines. The failure cases it produces — grasp slips, in-grasp topples, bounce-outs, stuck drawers — are failures that current benchmarks simply never produce. RoboTwin-Phys provides the code, configs, protocol, and data to measure them, together with a public leaderboard reporting success-rate deltas against paired no-drift baselines.
Motivation

Why benchmark physical drift?

A manipulation policy deployed in the real world almost never meets the physics it was trained with. Tabletops get waxed or wet, so grasps that used to hold start to slip. A box may be loaded or empty; a bottle may be half-filled, shifting its center of mass mid-grasp. Hinges and drawers age and resist. Workbenches are not perfectly level; camera mounts get bumped during maintenance. None of these changes alter what the scene looks like — yet each of them can decide whether a grasp holds, a placement stays, or a door opens.

Today's benchmarks certify robustness to appearance, not to physics. RoboTwin 2.0's demo_randomized suite varies backgrounds, lighting, clutter, table height (±3 cm), and language instructions — while every physical parameter (friction 0.5, restitution 0, fixed masses, level table, pinned camera) stays hard-coded. A policy can thus ace the official evaluation and still fail catastrophically the first time the world's physics drifts.

Physics is not a constant. Drag the sliders below — same scene, same action, only one physical factor changes each time — and watch outcomes diverge. If physics matters this much, we should measure it — with controllable perturbations, exact ground truth, and a protocol that turns "the policy failed" into an attributable, reproducible diagnosis.

Benchmark design

Factor selection is grounded in deployment reality. Each of the 13 factors maps to a routine, well-documented deployment event — a waxed tabletop, a half-filled bottle, an aging hinge, a bumped camera mount — rather than an arbitrary parameter sweep. Factors are grouped by where they act: contact (friction, restitution, joint dampings), object (mass, center of mass, geometry scale), workspace (table tilt, table height, external force), and sensor (camera distance, camera angle).

Tiered perturbations with measured failure envelopes. Each factor is swept over fixed tiers around its measured failure envelope. We define a factor's operating point as the tier where baseline success drops to 40–60%: hard enough to expose sensitivity, gentle enough to leave signal for comparing methods. Leaderboard entries are reported at these operating points.

Paired no-drift control. Every perturbed condition ships with a no-drift control run on the same seeds, so any performance change is attributable to the injected physics and nothing else.

Failure cases current benchmarks never produce

⚖️ Off-center CoM — the rolling pin swings down mid-grasp.
🎾 High restitution — the ball bounces out of the bowl.
🚪 Aged joint damping — the drawer barely opens.
What we observe
  • Camera-angle drift is the strongest observed failure mode. A bumped camera mount — a routine deployment event — is catastrophic for policies evaluated only with fixed cameras.
  • Contact-property drift is silent. Friction and damping changes leave RGB almost unchanged, so failures appear without any visual warning; only the contact-force logs reveal the onset.
  • Failures are structured. Timeline labels show a consistent injection → physical event → failure cascade, giving detection methods a measurable window to act before the episode is lost.

Dataset

The dataset is organized into four subsets with distinct roles. Probe interactions (~30K clips) are short, atomic behaviors — push, shake, drag, drop, push-door — crossed with factors, levels, and objects, designed for physics-perception training: learning to read physical properties from observations. Task episodes with drift (~5K episodes) inject physical drift into full bimanual tasks and keep both successes and failures, enabling step-level failure analysis in the task domain. Random++ mixes multiple randomized physics factors for robustness training. Finally, the no-drift control ships the official RoboTwin 2.0 data (27.5K episodes) so that every drifted episode has a paired baseline on the same seed.

Signals beyond RGB video

Every episode ships with far more than RGB video. Videos alone make drift a guessing game: a grasp slip and a mistimed grasp look identical on frame sequences. Our extra signals turn "the policy failed" into "friction dropped at step 100, the grasp slipped at step 132, the episode failed at step 150" — measurable, attributable, and learnable.

Label schema & collection protocol

Every episode carries the following schema:

factor | level | physics_gt (e.g. μ value) | seed | outcome (slide/topple/escape/…) | contact_log (250Hz impulses) | timeline (injection → physical event → failure)

Fair comparison is enforced at collection time. Fixed per-task seed lists guarantee the same initial states across all conditions; the software stack is pinned via env.lock; no seed re-rolling is allowed under perturbation. Because physics engines are only approximately deterministic, each (seed, condition) cell is repeated 2–3 times and reported as a seed-level success rate.

Evaluation Protocol

One unified evaluation configuration. All tasks and all methods are evaluated under a single shared protocol: each factor is evaluated at its operating point — the tier where baseline success drops to 40–60% — with the same seed lists, the same episode counts, and a paired no-drift control on the same seeds. This keeps every reported number comparable across methods and across factors.

Per-task adjusted configurations. Planner behavior can be sensitive to control settings under drift, so for a subset of tasks we individually fine-tune the evaluation configuration to keep the planner stable. These adjustments touch only the planner's control parameters — never the injected physics, the seeds, or the success criteria — and the exact configuration used for every (task, factor, level) cell is released with the benchmark for full transparency.

Fairness and repetition. Fixed per-task seed lists guarantee identical initial states across all conditions; the software stack is pinned via env.lock; no seed re-rolling is allowed under perturbation. Because physics engines are only approximately deterministic, each (seed, condition) cell is repeated 2–3 times and reported as a seed-level success rate.

Reporting. The leaderboard reports each method's success rate under drift alongside the paired no-drift baseline, and the success-rate delta between them, at every factor's operating point.
